# 项目关联候选与动态维度（1.3.0）

先明确项目，再获取候选，最后查询。`bi_get_user_tags`、`bi_get_user_label`、`bi_get_iap_sku_period_data` 的 `appList` 必填且至少一个非空项目编码；支持一个或多个项目。不能把未选择项目解释成全部项目，也不能用项目名称猜编码。

| 类型 | 候选工具及取值 | 用途 |
| --- | --- | --- |
| 自定义标签键 | `bi_get_user_tags` 的 `data` 字符串 | IAP 同期表、用户标签分析的动态分组 |
| 用户标签 | `bi_get_user_label` 的 `data` 中 `userLabel` | `abUserLabelList` 精确筛选 |
| 商品 ID | `bi_get_iap_sku_period_data` 的 `data` 字符串 | IAP 同期表的 `productIdList`；用户标签分析网页不提供商品控件 |

“自定义标签”是集合标题，不能直接作为具体分组。选择真实键之后构造 `custom_column_d<真实标签键>`，放入 `dimensionChecked`；`groupList` 仅包含其中普通维度。普通与模板查询均按这一网页规则执行。不要猜标签键、替换大小写或去掉候选值空白。服务端会重新获取候选并逐项校验。

`data: []` 表示所选项目集合没有候选，说明无可选项，不虚构默认值。多项目候选按接口返回集合使用，不声称每个项目都有该候选。切换项目或临时覆盖模板 `appList` 后，重新验证所有继承和新增标签、商品条件；旧候选失效时停止，不自动删条件。

自然语言示例（取值须来自真实候选）：

- “先列出 <PROJECT_CODE> 的自定义标签键、用户标签和商品 ID，再让我选择。”
- “查询我选定的两个项目，按日期、项目代号和刚才选择的两个自定义标签分组。”
- “沿用这个 IAP 模板，仅把项目改为 <PROJECT_CODE>；重新验证模板的商品和用户标签筛选，失效则告诉我，不保存模板。”
- “切换项目后如果没有标签，请报告空集合，不改查全部项目。”

`INVALID_ARGUMENT`：先补充明确项目或修正参数类型。`PARAM_NOT_ALLOWED`：完整候选没有指定值，拒绝整次查询。`PARAM_VALIDATION_UNAVAILABLE`：候选失败、结构异常或完整性不明，无法判断权限。自定义标签键和值的对应关系尚不能证明，动态键值筛选继续拒绝；动态分组支持不代表动态筛选已支持。候选存在也不代表拥有目标报表菜单、字段或业务数据权限。

IAP 的商品 ID 与部分指标互斥（例如投放消耗、新增用户、累计 ROI、合格率）；以契约 `productIdIncompatibleMetrics` 为准。冲突时询问用户选择保留商品筛选还是互斥指标，不删除商品条件后报告成功。用户标签分析表没有商品 ID 筛选控件。
